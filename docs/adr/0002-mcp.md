# ADR 0002: MCP for Agent Tools

Status: Accepted, 2026-10-17

## Context
The investigator agent calls three tools: weather, historical complaint SQL, and planned city work. Only one service calls them today.

## Decision
Expose each tool as an MCP server in `mcp/`.

## Why
- Credential isolation: the SQL tool's read-only role lives only in its server process, not in the agents service.
- Standard tool schemas, so adding or swapping a tool needs no agent code change.
- The same servers work from Claude Desktop or any MCP client for manual investigation and debugging.

## Alternatives Rejected
- In-process tool functions: less overhead and simpler, and a fair choice for three tools with one caller. Rejected for credential isolation and reuse. MCP is also partly a deliberate learning choice.

## Consequences
- Extra processes and a network hop per tool call, small next to LLM latency.
- A down tool server must surface as a tool error result, not crash the graph.

## Revisit When
Tool calls become a meaningful share of investigation latency.
